# 考核标准与测试体系（v0.3）

> 执行方式：`BASE_URL=<部署地址> npx tsx scripts/acceptance.ts`（模拟真实用户端到端）。
> 最近一次结果：2026-07-25 公网部署 **20/20 通过**。

## 考核维度

| 维度 | 用例 | 标准 |
|---|---|---|
| 数据面 | A1-A3 | 扫描/费率接口可用；**只有 HL 站内 S1**（无跨所）；≥10 个市场费率 |
| 确定性 | B1-B3 | 成本瀑布数学自洽（误差<1e-9）；决策与拒绝码严格一致；存在明确拒绝（“没有机会也是结论”） |
| 安全 | C1-C2, D1 | 未登录 401；伪造签名 401；未授权钱包禁止实盘 Agent |
| 身份 | C3, P2 | 真实钱包签名可登录；EVM↔inj 地址推导正确 |
| 积分 | P1-P3, E5 | 新用户赠送积分；流水可查；每 tick 扣费生效；不足自动暂停 |
| 引擎 | E1-E4 | 每 tick 产生可读决策日志；有合格机会开仓/无机会空仓行为一致；持仓具备收益/风险/费率观测字段；收益曲线快照 |
| 风控 | D3 | 资金输入被硬顶钳制（paper $100k / live $2k / 名义 $50k） |
| 收尾 | F1-F2 | 平仓生成 sha256 Receipt；Agent 可停止（连带平仓） |

## 未覆盖项（诚实清单，后续期补）

1. **实盘全链路**：ApproveAgent 签名→真实双腿下单→回滚，需真实 HL 账户+USDC 才能验（结构已按官方签名规范+SDK 实现，含单腿失败回滚）
2. **LLM 门实测开仓**：需等待出现 ≥门槛 净APR 的候选才走到 LLM 评估（key 已验证可用）
3. 积分充值链上扫描：需配置 `INJ_TREASURY_ADDRESS` 后用真实转账验证
4. 长时运行稳定性（内存/store 增长、HL 限频退避）→ 观察服务器 journal
5. funding 结算精度：paper 记账用连续累计近似，真实结算是整点批量

## 可行性结论

体系成立：数据（免key公开API）→ 确定性引擎 → LLM 建议 → RiskGuard → 执行（paper 已闭环，live 结构就绪）→ 观测（收益/风险/费率）→ 计费（积分）。核心风险不在技术而在策略经济性：当前市场基准费率下，24h 持有的净APR 常为负，**产品价值恰恰是把这个事实透明化**，Agent 只在费率异常升高的窗口出手。

# AI Agent 体系背景知识与交易 Agent 设计模式

> 补充 `ai-stack.md` 的深度背景：为什么这样选型、业界模式全景、以及交易场景的特殊约束。最后核对时间：2026-07-25

## 1. Agent 架构模式全景

| 模式 | 代表 | 机制 | 适用 |
|---|---|---|---|
| **ReAct loop** | 各家基础 agent | LLM 循环：思考→调工具→观察→再思考 | 开放式任务（调研、运维排查） |
| **Plan-and-Execute** | DeerFlow、Plan模式 | 先生成计划，再逐步执行、按需重规划 | 长链条任务，降低 token 成本 |
| **Graph/状态机编排** | LangGraph | 节点=函数/LLM调用，边=条件转移，checkpoint 持久化 | 需要人审插入、回滚、并行分支的工作流 |
| **多 Agent 协作** | supervisor/swarm 模式 | 角色分工（研究员/评审/执行者），消息传递 | 复杂决策需要对抗性审查 |
| **Workflow + LLM 节点**（本项目） | 自研 orchestrator | 确定性 pipeline，LLM 只占少数节点 | **流程本身确定、判断点需要智能**的场景 |

### 为什么交易 agent 必须是「确定性外壳 + LLM 内核」而不是反过来
1. **正确性**：ReAct 型 agent 每步都可能偏航；资金操作不允许「大概率正确」。循环、重试、下单逻辑必须是可单测的普通代码
2. **延迟与成本**：行情循环秒级跑，LLM 调用百毫秒~秒级且花钱 → LLM 只能在低频决策点介入（分钟/小时级）
3. **可审计**：监管/复盘要求每笔交易有可追溯理由 → LLM 输出必须是 schema 约束的结构化 JSON 落库，而非自由文本驱动行为
4. **失效模式**：LLM 挂了/超时/输出不合法时，系统必须能降级为纯规则运行或安全停机 —— LLM 是增强件，不是单点依赖

## 2. 交易 Agent 的标准分层（本项目蓝图）

```
L4 治理层   人类 + LLM：策略参数调整、标的白名单、事后复盘报告
L3 决策层   LLM(OpenRouter)：机会评估(可持续性/异常判断) → 结构化决策JSON
L2 信号层   纯代码：费率/基差/价差计算、扣费后收益估算、机会排序
L1 执行层   纯代码：订单状态机、双腿协调、重试/回滚、reconcile
L0 数据层   纯代码：WS/REST 采集、归一化、落库(SQLite)
            ⚠ RiskGuard 横切 L1-L3：任何指令过限额/止损/白名单校验才可执行
```

- **L3 的契约**：输入 = L2 产出的机会快照 + 历史上下文；输出 = `{action, symbol, size, confidence, reasoning, ttl}`（zod schema 校验，非法即丢弃）
- **降级路径**：L3 不可用 → L2 直接用保守规则出信号（或只平不开）；L0 断流 → 撤单+冻结

## 3. LLM 工程要点（OpenRouter 场景）

- **结构化输出**：一律 `generateObject` + zod schema；禁止解析自由文本
- **模型分层路由**：决策/复盘用强模型；摘要/清洗用便宜模型；OpenRouter 一个 key 全搞定，模型名做成配置
- **上下文构造**：给 LLM 的行情快照要**预计算、预压缩**（表格化数字，不丢原始 JSON），控制 token；prompt 版本化（`src/prompts/` 存文件 + 版本号落库，复盘可归因）
- **评估（eval）**：决策 JSON 全量落库后，可离线回放「LLM 决策 vs 纯规则 vs 事后最优」做持续评估——这是 AI 套利平台区别于脚本的核心资产
- **成本护栏**：按小时/日 LLM 调用预算计数器，超限降级为规则模式

## 4. 记忆与状态

- **短期**：当前持仓、未完成的双腿、活跃机会 —— 内存 + SQLite（崩溃恢复用，重启先 reconcile 交易所真实状态）
- **长期**：费率历史统计、每标的的历史决策与结果（喂给 L3 做 few-shot 上下文）、复盘结论
- 不需要向量库起步；SQLite 表 + 按 symbol 聚合查询足够，等有真实检索需求再升级

## 5. 何时升级到重框架（触发条件而非时间表）

- 出现 **需要人工审批插入执行链**（如大额调仓）→ LangGraph.js 的 interrupt/checkpoint
- 出现 **多策略 agent 竞争资金池** → supervisor 模式做资金分配
- 出现 **跨日长任务**（如逐步建仓一周）→ 需要持久化 workflow 状态机
在此之前，保持 orchestrator 为 ~300 行可读代码是竞争力而不是欠债。
